# meta-epics

PetaLinux layer for cross-compiling EPICS Base and, in later stages, EPICS support modules and IOC applications.

This repository currently contains only stage one: `epics-base` 7.0.10. Later modules are not added or built in this stage.

## PetaLinux Integration

The following procedure adds this layer to an existing PetaLinux project.

### 1. Place the Layer

Place the layer under the PetaLinux project's `project-spec/` directory:

```text
my-petalinux/
└── project-spec/
    ├── meta-epics/
    └── meta-user/
```

Use a symbolic link during development if desired:

```bash
cd my-petalinux/project-spec
ln -s /path/to/meta-epics meta-epics
```

### 2. Add the Layer

From the PetaLinux project root, run:

```bash
petalinux-config
```

Open:

```text
Yocto Settings -> User Layers
```

Add:

```text
${PROOT}/project-spec/meta-epics
```

Save and exit. PetaLinux writes the layer to `build/conf/bblayers.conf`.

Check the generated layer list:

```bash
grep meta-epics build/conf/bblayers.conf
```

Do not commit `build/conf/bblayers.conf`; it is generated by PetaLinux.

### 3. Verify Layer Visibility

PetaLinux projects must first load their bundled Yocto environment. From the
PetaLinux project root, use the path provided by the project:

```bash
source components/yocto/layers/poky/oe-init-build-env build
```

Some PetaLinux releases use `layers/core` instead of `layers/poky`:

```bash
source components/yocto/layers/core/oe-init-build-env build
```

After sourcing this environment, raw `bitbake` and `bitbake-layers` commands
are available for inspection. Do not run them before sourcing the PetaLinux
project environment.

Run these commands in the shell where the PetaLinux Yocto environment is
active:

```bash
bitbake-layers show-layers
bitbake-layers show-recipes epics-base
```

The output must list `meta-epics` and recipe version `7.0.10`.

## Project Configuration

Configure the installation prefix in `project-spec/meta-user/conf/user.conf`:

```bitbake
EPICS_PREFIX = "/opt/epics"
```

The recipe selects the EPICS target architecture from `TARGET_ARCH`:

```text
aarch64   -> linux-aarch64
other ARM -> linux-arm
```

Override it explicitly when needed:

```bitbake
EPICS_TARGET_ARCH = "linux-arm"
```

Zynq-7000 uses `linux-arm`; ZynqMP uses `linux-aarch64`. Machine-specific overrides are also supported:

```bitbake
EPICS_TARGET_ARCH:my-zynq-machine = "linux-arm"
EPICS_TARGET_ARCH:my-zynqmp-machine = "linux-aarch64"
```

### Verify Expanded Configuration

```bash
bitbake -e epics-base | grep -E '^(EPICS_PREFIX|EPICS_TARGET_ARCH|EPICS_HOST_ARCH|SRCREV|DEPENDS|RDEPENDS)='
```

The recipe fixes `EPICS_HOST_ARCH` to `linux-x86_64`. PetaLinux/BitBake
provides the target cross-compiler, `${TARGET_PREFIX}`, and target sysroot
automatically; no SDK compiler path needs to be hard-coded.

## Add to the Root Filesystem

Choose one of the following methods.

### User Rootfs Configuration

Add this line to `project-spec/meta-user/conf/user-rootfsconfig`:

```text
CONFIG_epics-base
```

Then open the rootfs configuration menu and confirm the package is selected:

```bash
petalinux-config -c rootfs
```

### Image Install List

Alternatively, add this to `project-spec/meta-user/conf/user.conf`:

```bitbake
IMAGE_INSTALL:append = " epics-base"
```

Do not use both methods at the same time.

## Build

Build the recipe first:

```bash
petalinux-build -c epics-base
```

Then build the complete image:

```bash
petalinux-build
```

The first build fetches EPICS Base from GitHub. Network access or a configured
source mirror is required unless the source is already present in `DL_DIR`.

## Verify Target Files

After booting the target, verify:

```text
/opt/epics/base -> base-7.0.10
/opt/epics/base-7.0.10/bin/<target-architecture>/
/opt/epics/base-7.0.10/lib/<target-architecture>/
/opt/epics/base-7.0.10/lib/perl/
/etc/profile.d/epics.sh
```

The target filesystem must not contain:

```text
/opt/epics/base-7.0.10/bin/linux-x86_64/
/opt/epics/base-7.0.10/lib/linux-x86_64/
```

The target Perl scripts require the `perl` runtime package.

## Troubleshooting

After sourcing the PetaLinux Yocto environment as described above, inspect the
recipe:

```bash
bitbake-layers show-recipes epics-base
bitbake -e epics-base | grep -E '^(EPICS_PREFIX|EPICS_TARGET_ARCH|EPICS_HOST_ARCH|SRCREV|DEPENDS|RDEPENDS)='
```

If `epics-base` is not listed, check `build/conf/bblayers.conf` and rerun
`petalinux-config`. If the layer is rejected as incompatible, compare the
PetaLinux Yocto release with `LAYERSERIES_COMPAT_epics` in `conf/layer.conf`.

## License checksum

The recipe uses the checksum of the `LICENSE` file from the pinned
7.0.10 commit. Yocto validates it during the license collection task.

## Target filesystem layout

```text
/opt/epics/base -> base-7.0.10
/opt/epics/base-7.0.10/
/etc/profile.d/epics.sh
```

Support modules install alongside Base under `/opt/epics/modules/<name>`, each
with a version-independent symlink:

```text
/opt/epics/modules/asyn -> asyn-4.46
/opt/epics/modules/asyn-4.46/
```

The target installation contains only `${EPICS_TARGET_ARCH}` binaries and
the architecture-independent EPICS Perl scripts. Host architecture
directories and host-only Python build helpers are not installed. The scripts
require the target `perl` package.

`epics-base` stages Base into the BitBake sysroot. Support modules are staged
the same way under `${EPICS_PREFIX}/modules/<name>`, so a module recipe depends
on its prerequisites and points `configure/RELEASE` at the staged symlink:

```bitbake
DEPENDS += "epics-base asyn"
EPICS_RELEASE_EXTRA = "ASYN = ${RECIPE_SYSROOT}${EPICS_PREFIX}/modules/asyn"
```

`EPICS_BASE` is always set to `${RECIPE_SYSROOT}${EPICS_PREFIX}/base`
automatically.

## Later modules

Planned dependency relationships:

```text
SNCSEQ -> SSCAN -> CALC -> ASYN -> STREAM
                 \       \-> BUSY
AUTOSAVE -----------> BUSY
XXX -> all selected modules
```

`asyn` 4.46 and `autosave` 6.0 are added first. `asyn` needs `libtirpc` for its
VXI-11 ONC RPC support and `rpcsvc-proto-native` for the hermetic `rpcgen`:

```bitbake
DEPENDS += "libtirpc rpcsvc-proto-native"
```
